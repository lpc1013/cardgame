## P2 · 存量质量升级（工程遗留项）

1. ~~**地点图高清化 108 张**~~：现存 145 张静态场景图里，37 张是 2560×1440 全屏档，**108 张只有 480×270**，按两档规矩只能走 14% 淡水印档（《项目对接文档》第八节 F3 遗留）。若要这 108 个地点升全屏铺底，需按 `tools/jm/` 即梦产线回收高清原件重产。
   **10-09 实测后判定：这不是观感缺口，别按这条产图。** 原稿称它"目前观感上最大的一笔"，量下来不成立：
   `.scene-bg`（`app.css:1104`）把**所有**场景底一律渲染成 `background-size: cover` + `opacity: .14` + `blur(1px)` + `grayscale(.25)`。
   把一张 2560×1440 真图按这条链跑一遍，再把它降到 480×270 跑同一条链，逐像素比对渲染结果：
   **平均亮度差 0.32/255（0.13%），p95 1.26**；边缘能量确实掉 25~34%，但那是落在一个总对比度已被压到约 36 级（0.14×255）的层上，
   折算下来仍是不到一个亮度级。也就是说：**分辨率在这条渲染链下几乎是不可见的，真正决定背景观感的是"处理参数"（opacity / blur / grayscale），不是源图像素。**
   重产 108 张 ≈ 432 次即梦抽卡、数小时与一笔积分，换来的是亚感知差异——不值。
   若日后要让背景"更像背景"，动 `.scene-bg` 的 opacity/blur 是十分钟的事，先量那一档再谈产图。
   （注：只有烘出 `motion/<剧本>_<场景>.webp` 的 24 幕走 `.scene-stage` 真背景档，不受此结论约束。）

2. **动效背景扩容**：动效 webp（1152×648 无缝循环，`tools/anim-forge/` 产线）现有 24 段，覆盖 24/511 幕。可按"一部一部铺开"的既定策略续产（样板 changjiang 已跑通）。
3. **暂不必升**：成就图标/主题样片 256×256（装饰位，够用）；舆图 1120×630（栏内展示，够用）。

## 刻意不产图的（保持 SVG/CSS，勿动）

- **四花色印章 / 层徽 / 墨铤图标 / 成就兜底纹章**：`currentColor` 随七套皮肤变色，是主题系统的活部件，换成位图会破坏浅/深两档与 `data-theme` 轴。
- **卡背（`dt-placard-back`）/ 宣纸纹理 / 大漆木框**：CSS 渐变与令牌体系，属 UI 壳层，非素材。
- **音效**：WebAudio 程序化合成（`engine/sfx.ts`），零素材依赖，无需音频文件。
