一、新发现

P1 情绪制对局出牌反馈文本全部丢失（UI 合同断链 · 实测实证）

断链机制：playEmotion 结算写入 lastResult（「接得严丝合缝」「防备松动了」）→ DuelView.clickCard 立即调用 revealEmotion(d) → revealEmotion 无条件执行 st.lastResult = null（duel.ts:113）→ React 批量提交的是「已清空的下一回合状态」，带反馈文本的中间状态永不渲染。
场景表现
对局进行中（每轮出牌后）共鸣/破防/失言文案不显示，只剩数值静默变化
胜利 / 失败结算正常显示（finished 守卫挡住清理）

影响面：13 个情绪制对局 / 全库 23 个对局（56%），波及 11 部剧本。对以文案为灵魂的权谋叙事游戏，是核心体验缺陷。

为何历轮未捕获：verify 的 BFS 只断言可胜性与状态可达，stateKey 不含 lastResult —— 这是「引擎正确、UI 合同断链」的结构性盲区。

修复（十行内）：① revealEmotion 不再清 lastResult（由下一轮结算自然覆盖）；② 或 UI 将 lastResult 存独立 state；③ verify 加断言「情绪局未 finish 时出牌后 lastResult 非空」，把反馈合同纳入回归。

P2 行令「必输序列」残留 3.1%，界面无征兆

64 种令签序列枚举（4³，玩家最优应对）：2 种必输（最差 2 分，如「器器器」），离 3 分门槛差 1 分。上一轮的「永久锁结局」已解除（败可再战），但单局内玩家会经历「怎么选都输」的困惑局且无任何提示。

修复（一行数据改动）：① 手牌 +1 备牌把最差分抬到门槛；② 门槛降 1；③ 界面提示「此巡牌势不济，可退席重入」。建议 ①。

P2 removeCard×钥匙卡：机制无防线（当前数据安全，未来地雷）

verify 第 5 组只断言「cond.card 有获得途径」，不建模"获得后被剧情移除"。实测 3 处命中（fuma 银票收入内廷 / fuma 烧银票 / qiuwei 烧银票进埋骨结局）均为设计性消耗；但未来若作者把无条件 removeCard 写在 cond.card 分支之前，软锁将伴随绿灯通过。

修复：verify 增交叉断言 —— removeCard 命中集 ∩ cond.card/notCard 引用集，命中即 warn（十行内）。

P2 物品「抽牌」卡空库抽 0 张，不洗弃牌堆

drawUp 的空库洗回逻辑未复用于「抽牌」道具效果（duel.ts:262-268 直接从 library shift）。全库 5 张受影响（i_wenji / i_sangpizhi / i_shigao / i_gongxiang 等）。牌库见底时使用，文案说「摸出两张」实际 0 张。

修复：抽牌效果前复用 drawUp 的洗回逻辑，约五行。
