所有标 ✔ 的条目均已亲自读码 / 推演复现路径确认；标 ◇ 的为方向成立但数字或细节未完全坐实。

## P0（可被玩家稳定利用 / 破坏核心系统）

### P0-1 ✔ 市集银两全程「本地态」，刷新即撤销亏损 → 赌坊无限刷钱
- 位置：`App.tsx:1612`（ShopView `local` state）、`App.tsx:1817-1821`（赌坊 tab 只写 `local.silver`）、`App.tsx:2539-2555`（SicboPanel）、`App.tsx:672-677`（仅「离市」→`afterShop` 才 `setSt` 提交）
- 机制：市集内所有买卖、开包、骰子输赢只改组件内 `local`；全局 `st` 与自动存档停在进市前。输光了 → F5 刷新 → 银两原样回来；赢了 → 点离市落袋。
- 复现：进市集→赌坊→押最大→勾选「出千」（七成胜面）→输了刷新重试→赢了离市。零风险无限银两，直接击穿市集经济与押注风控（M1 wagersLeft 用银两兜底的前提失效）。
- 修复方向：市进市即提交（每笔操作直接改 `st`），或离市/关窗统一走确认；至少把骰子结果即时落库。

### P0-2 ✔ 随从卡在银两未提交前已写全局 → 刷新白嫖随从；卖卡不销账
- 位置：`App.tsx:1645-1647`（买「人物」随从卡即时 `addRetinue(id)` 全局持久化），而扣银只发生在 `local`（1641-1643）；`App.tsx:1652-1662`（`sell` 只减 `local.bag/deck`，从不 `removeRetinue`）
- 机制：买随从卡 → 随从册（全局、跨剧本）立即+1；此时刷新，银两回滚、随从保留。反复买满 3 人 = 免费随从。另一条：买后可按半价卖回，牌从袋中消失但随从永久留存册中。
- 复现：阊门市集买「斥候」→ F5 → 银两未减、随从已在册。
- 修复方向：`addRetinue` 挪到离市提交时随 `local` 一并结算；`sell` 随从卡时同步出册（或禁卖已入册者）。

### P0-3 ✔ 物品卡绕过一切资源约束：情绪制绕言力/回合/话题上限，压制制绕单次伤害封顶
- 位置：`duel.ts:788-812`（`playItem` 不扣 yanli、不 `round++`、不进 topicHits 计量）、`duel.ts:814+`（`applyItemEffect`：破防 气力-4 / 共鸣 -3 直接改 HP，不经 `TURN_DAMAGE_CAP`）
- 机制：数据层已备好弹药——`sichou.ts` i_yinpiao2（共鸣22）/i_mixin（破防20）/i_anyun，`qiuwei.ts` i_moji（破防，price 0 白送）:38 + i_siyin:39，`qinhuai.ts` i_xiang/i_zhang:33-35，`fuma.ts` i_zhu/i_dao/i_yu。情绪制里一叠物品可在对手出牌轮之外连拍：guard 清零+共鸣直灌，不耗任何节奏资源；pressure 里点差封顶 6 的 M1 门禁对物品完全形同虚设（-4 额外于封顶伤害之上）。
- 加重项：`verify.mts` 的 BFS 全链路从不使用 `playItem` → 可胜性证明系统性低估玩家上限伤害，unwinnable 断言也可能被物品打穿（剧情杀 d_deliver 7/20 血线 + 物品连拍未必成立）。
- 修复方向：情绪制物品计入 yanli 等值消耗或每局限 1；压制制物品伤害并入 cap 结算；verify 增加「含物品」分支穷举。

### P0-4 ✔ lastPlay 战报渲染不走 redactLog / oppHidden → 隐藏信息泄漏（M7 P1-1 修复不完整）
- 位置：`App.tsx:2247`：`他打出「{duel.lastPlay.oppCard?.name}」（{duel.lastPlay.oppCard?.power}）` 无条件渲染；M7 的 `redactLog` 只罩住了 `duel.log` 系。
- 机制：gambit 局对手下一手本应▓▓▓，对手主攻结算后 `resolveOppAttack` 写入 `lastPlay.oppCard`，这行直接印出真名+点数。玩家据此几回合内还原整条 script 循环——反背板（M3）与观牌经济全部作废。
- 修复方向：该行同样过 `oppHidden && knownLevel !== "card"` 门（或未达第 4 回合耳报条件时遮蔽牌名）。

## P1（平衡/验证体系失真）

### P1-1 ✔ 首回合极限伤害门禁恒真（M1 防 OTK 已失效）
- 位置：`verify.mts` `firstTurnMaxDamage`：伤害经 `playPressure` 结算，而 `playPressure` 自身已把单次交换钳到 ≤6 → `before - d.hpOpponent` 数学上不可能 > `TURN_DAMAGE_CAP`，门禁永远绿。
- 加重：`verify.mts:493` 调用处仍传裸 `cfg`（未套 `vc`），scriptVariants 下用主 script 首牌测——与 M3 全量变体部署脱节。
- 修复方向：门禁改为在引擎外算「理论值」（base×势1.5 + 蓄势×2×2 + 物品爆发 + 克色+1），或封一个不 clamp 的结算旁路供测量。

### P1-2 ✔ verify 的「可胜」是全知视角可胜
- 位置：`verify.mts:186` 及 `pressureBest` 全程：BFS 每一步直接取 `cfg.script[d.round % …]` 作 `oppId` 入参——即测试者已知对手每一手且无雾。实机里 gambit/hidden 局第 1~3 回合根本看不到下一手，UI 推荐与穷举找出的胜线对盲人玩家不可执行。
- 影响：unwinnable/可胜断言与实机体验两张皮；「剧情杀不可胜」结论尤甚（我方 BFS 全知还打不穿，玩家更打不穿 → 这条恰好保守；但「普通局可胜」是激进侧误报）。
- 修复方向：可胜性判定引入信息约束（未知下一手时按花色分布取最坏情况），至少在 gambit 局标注「全知上限」。

### P1-3 ✔ verify 测试卡组是玩家永远组不出的牌堆
- 位置：`verify.mts:66-68` `v2Loadout`：取 `sc.cards` 全部非资源卡，无视 `deckLimit(12)`、无视商店限购/结局解锁/钥匙卡。
- 影响：同 P1-2，「可胜」是在超模装备下证明的。
- 修复方向：以 `deckLimit` 为界枚举若干代表性合法子集，或取「商店可购全集 ∩ deckLimit 贪心」。

### P1-4 ✔ 对手低血正反馈：残血必「蓄力」＝把回合白送
- 位置：`duel.ts:509-514`（`defensiveHpPct` 触发防御性 charge）→ `duel.ts:522-526`（`handOffToOpponent` 的 charge 意图立刻交回回合，不出牌）。
- 机制：对手血量 <30% 后每一回合都选蓄力+过牌，永不再进攻。玩家站在靶前免费输出到死——押注局（1.6 倍赔率）打穿 AI 只剩「把血磨到 30% 然后白嫖」一条线，赌局变提款。
- 修复方向：防御蓄力限一次或按概率；残血反而提高进攻权重（背水一战）。

### P1-5 ✔ 刺探/收买后仍可押注 → 先看房再下注
- 位置：`duel.ts:1042-1084`（`duelSpend` 不写 `lastResult`、不动 `round`）× `App.tsx:2037`（`wagerOpen` 以 `round===0 && !lastResult` 为闸门）。
- 复现：开局先【刺探·下一手】或【刺探·案下】看清敌招/有无埋伏，再决定押不押、押哪档。押注的信息不对称被随从白送。
- 修复方向：wagerOpen 追加 `scoutLeft===cfg初始 && !insiderActive`，或随从动作也写 lastResult。

### P1-6 ◇ 卡包期望值为正：商行打点包是台印钞机（与 P0-1 合流更凶）
- 位置：`sichou.ts:304`：45 两、抽 2、池含 s_yin50+s_yin100（`App.tsx:1673` 资源直接折银）。仅资源项期望回银 = 2×(150/5) = 60 两 > 45 成本；非资源三张（i_yinpiao2 等）还能按半价卖回再回收。大数定律下无限买包 = 稳定净赚。
- 注：agent 报的 +25.8/包数字未复算一致（我的口径 +15 起，含卖卡回收更高），方向坐实、精确值存疑。
- 修复方向：抬价或削池；至少让 pack 期望 ≤0（对齐书吏夹带包 25 vs ~24 的现状）。

## P2（体验/规则一致性）

### P2-1 ✔ light 回合【破招】零成本宣言
- 位置：`duel.ts:748-759`：phased 轻回合破招不耗 AP（v2 非轻耗 1、legacy 也耗 1）。错了只亏节奏，对了免费作废敌方主攻——配合对手意图可预测性，形成「每轻回合白赌一发」的零风险线。M5.1 修的是情绪制，这条压制制等价物漏网。
- 修复方向：light 局破招也应有代价（如宣言错则下张 -1）。

### P2-2 ✔ classic/light 路径应手不消耗任何东西
- 位置：`duel.ts:582`（仅 `rules==="v2"` 才 discard）。classic 无手牌概念（从全 deck 选），应手等于无限次免费接招，唯一天花板是「招式用老 -2」。d_deliver 等剧情杀靠数值兜底，但任何新 phased+classic 局都会继承这个洞。
- 修复方向：引擎注释标明「phased 仅对 v2 设计」，或给 classic 应手加每回合 1 次限制。

### P2-3 ✔ 开包开出重复非资源卡 = 静默吞银
- 位置：`App.tsx:1674-1675`：dup 不入袋不折银，只在结算弹窗打个角标——钱花了、东西没了、无补偿。注释自称「避免静默吞银」，实际只是把吞银改了个展示方式。
- 修复方向：dup 折半价银。

### P2-4 ✔ 琉璃试珠「白看」是假的：预览与购买各摇各的
- 位置：`App.tsx:1684-1697`：`peekPack` 独立 `Math.random`，与随后 `openPack` 的摇取无关。文案明说「看完再决定买不买」，给玩家的却是无关样本——诱导性 UI。
- 修复方向：peek 结果锁定为该包的下次开取（seed 化）。

### P2-5 ✔ verify 警告不参与退出码，unwinnable 豁免警告可长期烂尾
- 位置：`verify.mts:637`（`process.exit(failures ? 1 : 0)`）。M7 新增的两条「旧豁免已失效」警告只刷屏不拦截。可接受，但建议在 CI 文案里明示「警告 ≠ 通过」。
